## 1. Overview

This project implements a front end for a toy programming language called MiniLang+, using ANTLR4 to perform lexical analysis and syntactic parsing. The system tokenizes source code, validates its structure against a defined grammar, and produces a parse tree for valid programs. Syntax errors are reported with line numbers.

## 3. Parser Design (MiniLangParser.g4)

The parser implements the full MiniLang+ grammar using ANTLR4's `parser grammar`. Key design decisions:

**Operator precedence via grammar stratification.** Rather than using ANTLR's built-in precedence climbing, the grammar encodes precedence explicitly through layered non-terminals: `Expr → OrExpr → AndExpr → EqualityExpr → RelExpr → AddExpr → MulExpr → UnaryExpr → Primary`. Lower-precedence operators appear higher in the grammar hierarchy, ensuring they bind more loosely.

**Left-recursion elimination using primed rules.** Rules like `AddExpr'` and `MulExpr'` handle left-associativity without left recursion, which ANTLR's LL(*) parser cannot handle directly. The pattern `A → B A'` with `A' → op B A' | ε` achieves left-associativity in a top-down parser.

**Optional else clause.** `ElsePart → 'else' Stmt | ε` models the optional else branch. ANTLR resolves the classic dangling-else ambiguity by default using the nearest-if rule.

**For loop structure.** The `ForStmt` rule uses `AssignStmt` (without semicolons as part of the rule) separated by explicit `;` tokens, matching the spec exactly.

## 5. AI Usage Reflection

Several AI tools were used during this project, and this section discloses exactly what was generated, how it was used, and what we learned from the process.

**What was AI-generated.**
`Main.java` was fully generated by AI, as noted in the file's header comment. We provided the tool with the project specification and asked it to produce a driver class that ties the lexer and parser together, prints a formatted token table, and displays the parse tree. The output included ANSI color-coding for readability, a custom error listener class, and a recursive tree-printing method. Parts of this report (sections 2 and 3) were also drafted with AI assistance — we described our design decisions and used AI to help structure and phrase them clearly.

**How we used it.**
We did not copy output blindly. After receiving `Main.java`, we read through the entire file to understand what each method does, verified that it correctly referenced our lexer and parser class names, and confirmed it compiled and ran without modification. For the report sections, we reviewed the generated text against the actual grammar files to make sure the descriptions were accurate.

**What we verified ourselves.**
We wrote `MiniLangLexer.g4` and `MiniLangParser.g4` ourselves, which are the core deliverables of the project. We designed the token ordering in the lexer (keywords before identifiers, multi-character operators before single-character ones) and the full expression precedence hierarchy in the parser. We also wrote all four test programs to exercise specific valid and invalid constructs, and ran them manually to confirm the expected behavior.

**What we learned.**
Reviewing `Main.java` gave us a practical look at how ANTLR integrates with Java — specifically how `CharStreams`, `CommonTokenStream`, and `ParseTree` work together. We also learned that AI-generated code is not always consistent with project-specific details: the pre-compiled `MiniLangLexer.java` that was initially provided used different token names (`STAR`, `LPAREN`) than our own `.g4` file (`MULTIPLY`, `OPAREN`), which required us to regenerate it. This taught us the importance of checking generated output against our own specifications rather than assuming it is correct.
